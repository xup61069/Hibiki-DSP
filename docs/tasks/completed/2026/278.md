# Issue 278 handoff

## Objective

根因修復 control-model engine smoke 的「scene ack 間歇失敗」。調查發現**兩個獨立根因**，
其一為真正的 C++ 引擎 crash：

1. **Engine stack overflow（0xC00000FD）**：`hibiki_engine_preview` 以 Windows 預設 1 MiB
   堆疊執行；主迴圈 inline drain IR prepare（WAV parse + kernel 合成）在負載下爆棧，行程
   死亡 → control pipe 關閉 → client `EndOfStreamException` → Degraded → ack 失敗。
   修法：`target_link_options(/STACK:16777216)`，比照 contract_tests 既有前例
   （tests/CMakeLists.txt 已有 `/STACK:8388608` 同款註解）。
2. **吞掉的例外不可觀察**：`SendCommandAsync` 的 `catch (Exception)` 只回 false。新增
   `LastSendDiagnostics` 屬性記錄被吞例外，smoke 失敗訊息帶入 status/connection/diag。

另確認 #272 已合併的 bounded-poll 屬同族防護，本切片將 volume reconcile 也改為同一模式；
並證實 `VolumeGeneration == 1UL` 斷言僅對全新引擎成立（跨 session 階梯遞增屬 harness 假象，
正式 wrapper 每回啟動新引擎）。

## Acceptance

- 負載下（4 條 CPU 壓力 job）連續 4 次 wrapper smoke 全過；修復前同條件 ~80% 失敗。
- Engine 行程不再於 smoke 中死亡（6 連跑後仍存活；修復前單次即 0xC00000FD 死亡）。
- ack 失敗時錯誤訊息含 status/connection/LastSendDiagnostics 三項事實。
- 僅觸碰 scope_globs 檔案；無 RT/DSP/driver 行為變更。

## Completed

  harness 共用長命引擎所致，非產品缺陷）；真正死因為 stack overflow crash。
- `/STACK:16777216` 加至 hibiki_engine_preview；`LastSendDiagnostics` 診斷屬性 + smoke
  訊息強化；volume reconcile 改 bounded poll（與 #272 同模式）。
