# Issue 201 handoff: PortCls WaveRT Adapter Driver Entry and Subdevice Registration

## Objective

Provide the MS-PL PortCls adapter driver entry (`DriverEntry`), device object creation (`AddDevice`), subdevice registration (`PcRegisterSubdevice` for WaveRT miniports/ports), and PNP/Power dispatch in `driver/wdk/` that wires all four endpoints (Main, Low Latency, Surround 7.1, Virtual Mic) into the standard Windows audio driver life cycle without linking GPL user-space code.

## Acceptance

- Implement `DriverEntry` initializing PortCls driver object and registering `AddDevice` entry point.
- Implement `HibikiAddDevice` creating audio adapter device extension and registering adapter with PortCls.
- Implement `HibikiStartDevice` calling `PcNewPort` (`CLSID_PortWaveRT`), initializing `HibikiMiniportWaveRtV1` for each endpoint, and registering subdevices via `PcRegisterSubdevice` with unique endpoint names.
- Implement PNP and Power dispatch handlers (`IRP_MN_START_DEVICE`, `IRP_MN_STOP_DEVICE`, `IRP_MN_REMOVE_DEVICE`, `PowerDeviceD0`, `PowerDeviceD3`).
- Retain strict MS-PL licensing, non-blocking real-time audio paths, and zero GPL user-space linkage.
- Update `tools/driver-source-check.ps1` to enforce adapter driver entry coverage.
- Pass all local gates and record anonymous evidence.
