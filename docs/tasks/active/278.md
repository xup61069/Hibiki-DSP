# Issue 278 handoff: scene-switch ack intermittent false root-cause

## Objective

找出 `EasyControlViewModel.SelectSceneAsync("movie")` 在 control-model engine smoke 中
間歇回傳 `false` 的確切 `SendCommandAsync` 失敗路徑，並在不遮蔽 ack 失敗訊號的前提
下做 product-side 修復（timeout/retry/serialization 擇一，與 busy-merge 模型一致）。
控制面專屬，不影響 RT thread 規則。

## Acceptance

- 以可重跑的本地診斷（`.local/`，不進 Git）辨識四條 false path 中實際觸發的一條，
  並記錄重現統計。
- Product-side 修復限 `apps/control-model/EasyControlViewModel.cs`／`IpcProtocol.cs`，
  不以盲目 retry 遮蔽真實 ack 失敗；行為改變記錄於 evidence。
- `tools/control-model-engine-smoke.ps1` 的 StatusText 儀器化屬 follow-up：該檔目前被
  active lane #272（PR #276）佔用，scope 重疊禁止同時修改。
- 必跑 gates 通過：doctor、handoff-check（issue + full）、docs-check、source-policy、
  source-only-ci-check、control-model-check、winui-shell-check、verify、
  `git diff --check`。
- 不宣稱 physical audio / driver / signing 能力。

## Completed

- 已確認 smoke 全鏈無 caller token：`SendCommandAsync` 內 `OperationCanceledException`
  路徑在預設 token 下不可達；false 只能來自 (a) 入口/gate 內 `!IsConnected`、
  (b) gate 後 silent recheck、(d) 非 Ack reply、(e) pipe IO exception。
- 已以 `.local/diagnostics/scene-ack/`（不進 Git）重現並鎖定實際路徑：**不是**
  timeout／retry／serialization 問題，而是 engine 端 crash——
  `hibiki_engine_preview.exe` 在 PrepareIr 之後緊接的 SceneApply transaction 中以
  **STATUS_STACK_OVERFLOW（0xC00000FD，exit code -1073741571）終止**；client 端看到
  `EndOfStreamException: Control pipe closed mid-frame` → generic catch → false。
- cdb second-chance 擷取顯示 main-loop frame（+0x2907f）單一 frame 約 626 KB，
  加上 `AudioEngineModel::prepare_ir` 的 ~256 KB stack-local `IrConvolverV1`，
  在預設 1 MB stack 上 IR prepare + SceneApply 背對背執行時觸發溢位；build layout
  差異解釋了原本「1-in-3 到整批失敗」的間歇性。
- Fixes：
  - `CMakeLists.txt`：`hibiki_engine_preview` 於 MSVC 下 `/STACK:8388608`（比照
    `hibiki_contract_tests` 既有先例）。
  - `src/hub/src/audio_engine.cpp`：`prepare_ir` 的 convolver candidate 改為 heap
    配置、fail-closed on allocation failure；移除最大的可避免 stack 消耗。
  - `apps/control-model/EasyControlViewModel.cs`：新增 bounded
    `LastCommandFailureDetail` 觀察面，記錄 `SendCommandAsync` 六條路徑的確切原因；
    不改變任何 fail-closed 語意，供 host／後續 smoke 儀器化使用。
- 重現統計：修復前進入 scene 階段的 16 輪中 13 輪 EndOfStream 失敗、3 輪通過；
  修復後 fresh-engine-per-round 20/20 通過（scene ack 典型 2 ms），原始 smoke script
  連續 5/5 通過。engine crash 完全消失。
