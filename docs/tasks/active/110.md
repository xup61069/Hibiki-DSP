# Issue 110 handoff

## Objective

Add `sync_scheduler_to_timeline_store_v1`: export every scheduler timeline into a
`Vst3TimelineFileStoreV1` (atomic replace per file) and report store entries absent
from the scheduler as stale candidates into caller-owned storage — deletion stays an
explicit caller decision. Completes the bidirectional persistence story with #72.

## Acceptance

- Empty scheduler exports zero and reports every pre-existing store ID as stale.
- Scheduler timelines export successfully; store.load round-trips them byte-stably;
  a corrupt pre-existing file under an exported ID is replaced, not preserved.
- Store IDs absent from the scheduler are reported stale exactly once each;
  undersized stale destination fails closed with the true total count and no partial
  listing.
- Per-entry save failures count as skipped without aborting; closed store returns
  invalid_argument with zeroed result.
- No CMakeLists change; no IPC frame, schema file, RT-thread, driver or
  permanent-identity change.
