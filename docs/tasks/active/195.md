# Issue 195 handoff: PortCls WaveRT Filter Descriptor and Topology Tables

## Objective

Provide the MS-PL PortCls filter descriptor (`PCFILTER_DESCRIPTOR`) and KS topology tables in `driver/wdk/` that define streaming and bridge pins, volume and mute nodes, connection topology graphs, and property automation tables for all four endpoints (Main, Low Latency, Surround 7.1, Virtual Mic) dispatching into `HibikiPropertyDispatchV1` and `endpoint_topology_v1` without linking GPL user-space code.

## Acceptance

- Implement PortCls `PCFILTER_DESCRIPTOR` generation for each endpoint index (Main, Low Latency, Surround, Virtual Mic).
- Define `PCPIN_DESCRIPTOR` tables for streaming WaveRT pin (KSPIN_COMMUNICATION_SINK/SOURCE, float LPCM datarange) and bridge physical pin (KSPIN_COMMUNICATION_NONE, KSNODETYPE_SPEAKER/MICROPHONE).
- Define `PCNODE_DESCRIPTOR` tables for `KSNODETYPE_VOLUME` and `KSNODETYPE_MUTE` with automation tables binding `KSPROPSETID_Audio` to `HibikiPropertyDispatchV1`.
- Define `PCCONNECTION_DESCRIPTOR` tables connecting streaming pins through mute/volume nodes to bridge pins.
- Wire `HibikiMiniportWaveRtV1::GetDescription` and `DataRangeIntersection` to the filter tables.
- Retain strict MS-PL licensing, non-blocking real-time audio paths, and zero GPL user-space linkage.
- Update `tools/driver-source-check.ps1` to enforce filter descriptor coverage.
- Pass all local gates and record anonymous evidence.
